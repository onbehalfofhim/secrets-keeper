# Client scenarios

Пакет `cmd/client` содержит сценарий проверки основных бизнес-сценариев
работы сервера Secrets Keeper через gRPC API.

Это не production CLI-клиент. Пакет предназначен для ручной
интеграционной проверки сервера после его запуска.

## Назначение

Сценарий последовательно выполняет основные операции:

- регистрацию пользователя;
- авторизацию пользователя;
- получение JWT и проверку `expires_in`;
- создание текстового секрета;
- получение секрета;
- обновление секрета;
- повторное получение секрета после обновления;
- получение списка секретов;
- удаление текстового секрета;
- проверку отсутствия удалённого секрета;
- создание binary-секрета;
- загрузку файла через gRPC client-side streaming;
- скачивание файла через gRPC server-side streaming;
- сравнение исходного и загруженного файла;
- получение metadata binary-секрета;
- удаление binary-секрета;
- проверку отсутствия удалённого binary-секрета.

При успешном прохождении всех основных сценариев клиент выводит:
```text
========================================
MAIN SCENARIOS PASSED
========================================
```

После выполнения основных сценариев дополнительно запускаются:

### security tests:
Проверяет изоляцию данных между двумя пользователями

Проверяются попытки:
- User B получить secret A;
- User A получить secret B;
- User B изменить secret A;
- User A изменить secret B;
- User B удалить secret A;
- User A удалить secret B;
- User B скачать файл User A;
- User B изменить файл User A;
- увидеть чужой секрет через `ListSecrets`.

При успешном прохождении проверки изоляции между пользователями клиент выводит:
```text
========================================
ALL SECURITY TESTS PASSED
========================================
```

### negative gRPC tests:
- Register с пустым login;
- Register с пустым password;
- Register с существующим login;
- Login с неправильным password;
- Login несуществующего пользователя;
- Login с пустым login;
- Login с пустым password;
---
- Create с nil secret;
- Create с пустым payload;
- Get с некорректным UUID;
- Get несуществующего секрета;
- Update с nil secret;
- Update без ID;
- Update несуществующего секрета;
- Delete с некорректным UUID;
- Delete несуществующего секрета;
---
- upload без chunks;
- upload с пустым secret_id;
- upload с некорректным UUID;
- upload в несуществующий секрет;
- upload файла в TEXT-секрет;
- использование разных secret_id в одном stream;
---
- download с некорректным UUID;
- download несуществующего секрета;
- download TEXT-секрета через BinaryService;
- download binary-секрета до загрузки файла.

При успешном прохождении всех негативных сценариев клиент выводит:
```text
========================================
ALL NEGATIVE gRPC TESTS PASSED
========================================
```
----
При успешном прохождении всех сценариев клиент выводит:

```text
========================================
ALL CLIENT SCENARIOS PASSED"
========================================
```

## Запуск

Перед запуском необходимо:

1. Запустить PostgreSQL.
2. Применить миграции.
3. Запустить Secrets Keeper gRPC server.

```bash
go run ./cmd/client
```
или 
```bash
make scenarios
```

По умолчанию клиент подключается к: localhost:50051
